# 封面设计规范（HTML 渲染版）

## 为什么不用生图服务

封面**必须用 HTML/CSS 手绘 + headless Chrome 截图**，不用 ImageGen / baoyu-cover-image。理由：

| 问题 | 生图服务 | HTML 渲染 |
|---|---|---|
| 中文 | 常出乱码、缺字、造字 | 系统字体，100% 准 |
| 改一个字 | 整图重生成，结果不可控 | 改 HTML 重渲，所见即所得 |
| 水印 | 带「AI 生成」水印，要裁底部 80px | 无 |
| 成本 | 消耗积分 | 零 |
| 系列一致性 | 每次风格漂移 | 套模板，三篇文章一个家族 |

代价是前期要写一次 HTML。`templates/cover-feed.html`、`templates/cover-square.html` 是现成模板，改字即可。

## 尺寸

公众号封面有两处用到，两个尺寸都要出：

| 用途 | 画布 | 2x 出图 |
|---|---|---|
| 封面大图（2.35:1） | 900×383 | 1800×766 |
| 封面方图 / 分享缩略（1:1） | 400×400 | 800×800 |

渲染必须加 `--force-device-scale-factor=2`，否则公众号里会糊。

## 布局结构

**feed（900×383）** 左右分栏，`flex 0 0 530px` + 右侧视觉锤区：

```
┌──────────────────────────┬──────────────┐
│ kicker（灰，大字距）      │   小字引题    │
│ 主标题（80px 白，关键     │   巨大单字    │
│   词橙色 em）            │   150px 白    │
│ 副标（24px，两行）        │   英文小注    │
│ 橙渐变下划线             │              │
│ 三个胶囊标签（16px）      │              │
└──────────────────────────┴──────────────┘
```

**square（400×400）** 居中竖排：kicker → 主标题（42px）→ 小字引题 → 巨字（100px）→ 一行副标 → 橙线 → 三标签。


## 文案六要素

封面只放六个元素，多一个就乱：

1. **kicker**：来源或场景，2–8 字，灰、字距 0.24–0.30em。例：「正经项目经理的」「资治通鉴 · 才德论」
2. **主标题**：4–6 字，**不是文章标题**。文章标题太长，封面上会挤成一团。例：文章《35 岁，你的简历死在算法手里》→ 封面标题「简历没人看」
3. **副标**：文章的核心结论，一行或两行，24px
4. **视觉锤**：**一个巨大汉字 + 一句英文小注**。它决定封面还看不看。例：「找 / FIND, NOT WRITE」「筛 / FILTERED」「炸 / ONE WEEK TO GO」
5. **橙渐变下划线**：宽度 112px，固定装饰
6. **三个胶囊标签**：写文章里的具体场景或数字，**不写抽象词**。例：「会议 → 台账」「变更 → 影响面」「周报 → 风险信号」

## 铁律

- **封面不复用正文图片**。正文首图是信息图（讲道理），封面是海报（抓眼球），两张图职责不同，各做各的。
- 主标题必须能一眼读完，宁短勿长。
- 标签一律用具体名词/数字，禁用「方法论」「最佳实践」这类空词。
- 改字后必须重渲并重看成品图，不能只看 HTML。

## 实测踩过的排版坑

做封面时逐个检查，这几条最常撞：

| 现象 | 修法 |
|---|---|
| 右侧巨字把左区挤到溢出 | 左区固定 `flex:0 0 530px`，右区 `padding:0 40px`，别让两边都自适应 |
| 标签换行或顶到画布外 | 三标签总宽控制在 380px 内；feed 用 16px、square 用 12px |
| 副标折成三行把标签顶出画布 | 副标最多两行，且提前算高度：kicker+标题+副标+线+标签 ≈ 260px < 383px |
| 英文小注过长撞右边缘 | 控制在 20 字符内，15–16px、字距 0.08em |
| 大标题挤成一坨 | 字号 80px 时最多 6 字；字距 0.04em |

## 渲染

```bash
bash scripts/render_cover.sh {ART}/diagrams/cover-feed.html
bash scripts/render_cover.sh {ART}/diagrams/cover-square.html
```

文件名含 `feed` → 900×383，含 `square` → 400×400，成品自动落到 `{ART}/images/`。

脚本不支持的尺寸一律报错退出，**不猜尺寸**（猜错会出一张比例不对的图，公众号里被裁得莫名其妙）。

## 封面不进正文

发布脚本不传封面文件（frontmatter 的 `coverImage` 在浏览器模式下不生效），所以：

- 成品 PNG 交付用户，由用户在草稿箱里手动「上传本地封面」
- 正文首图照常插在文章开头，与封面是两张不同的图

## 变体：照片封面（B 类个人叙事）

v2.0.0 起，个人叙事类文章**优先用真照片做封面**，设计版降为备选。模板 `templates/cover-photo-feed.html` / `cover-photo-square.html`，完整流程见 `references/photo-handling.md`。

与上面设计版的区别：

| 项 | 设计版（A 类） | 照片版（B 类） |
|---|---|---|
| 视觉锤 | 右侧一个巨大汉字 + 英文小注 | 照片主体本身 |
| 底色 | 固定深蓝黑渐变 + 橙/蓝光晕 | 照片 + 深色渐变遮罩 |
| feed 布局 | 左文字 530px / 右巨字区 | 左深底文字 500px / 右照片区 |
| square 布局 | 居中竖排 kicker→标题→巨字→副标 | 照片全幅铺底，标题在上、副标在下 |
| 调参重点 | 主标题字数、标签总宽 | `background-position` 让主体可见、`background-size` 控主体大小 |

照片版两个必检点：① 主体不能被左侧文字区或渐变压住；② square 的 `.desc` 是绝对定位，**必须自带 `text-align:center`**，否则贴左边缘。

⚠️ 用照片封面时仍保留设计版文件（`cover-feed.png` / `cover-square.png`），用户随时可换回。
