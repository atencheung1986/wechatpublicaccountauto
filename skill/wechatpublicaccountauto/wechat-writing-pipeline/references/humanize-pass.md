# 去 AI 味：流水线执行尺度

`humanizer-zh` 的 `references/wechat-pipeline-constraints.md` 点名要读这份文件。它回答的是「改到什么程度算够」，不是通用写法（通用写法在 humanizer-zh 里）。

## 输入与输出

- 输入：`{ART}/02-draft.md`
- 输出：`{ART}/03-humanized.md`，**只改一轮**，就地改写，不把改写说明写进正文
- 字数：**A 类（行业/观点）纯正文 2500–5000 中文字**（低于 2500 要补，高于 5000 要砍）；**B 类（个人叙事）不适用下限**，1200–2000 即可，注水会毁掉叙事的力气。体裁判定见 `references/genre-routing.md`。

## B 类专项：去味的重点是「删虚构细节」

个人叙事的稿子通常本来就没有套话和排比，按 A 类那套使劲改反而会越改越顺、越改越像 AI。B 类只做三件事：

1. **逐段对照用户原始叙述**，凡是原话里没有的具体名词 / 数量 / 动作 / 环境，一律删掉（例：两公斤猫粮、半分钟、僵持两分钟、走出去十几米、转了两圈、洗食盆拎回家）
2. 保留用户真说过的事实和克制的心里话，不动节奏和留白
3. 对账三件事：数字集合、二级标题数、图片引用数与初稿一致

⚠️ 别为了「补到 2500 字」去加机制说明——B 类补字就是补虚构。

## 本流水线的专项要求

1. **声口**：观点/行业专栏类稿件，允许第一人称和锋利判断，但情绪必须钉在已知机制、成本、后果上，不能靠形容词制造。正式报道类用克制事实声口，不注入第一人称愤怒。
2. **结构保留**：唯一一级标题、全部二级标题、表格、图片引用、frontmatter，一个都不能少。
3. **事实零改动**：数字、来源、年份、限定词原样保留。改完跑 `fact-check.md` 末尾的对账脚本。
4. **标题**：保持信息锚点，≤32 字。用户已拍板的标题**不要改**——标题是阶段 2 门禁定下来的，去味阶段无权推翻。
5. **公式结构优先拆**：「不是 A，而是 B」「不仅 A 而且 B」「挑战与展望」模板、每节同构的排比，这些是最明显的机器痕迹。
6. **金句处理**：空洞口号直接删；有事实或机制支撑的判断句可以留，但后面最好补半句说明它为什么成立。

## 公众号特有的痕迹

- 「写在最后」「总结一下」「总而言之」这类模板小标题 → 换成指向具体动作的小标题
- 段落尾总是反问或金句 → 改成事实、代价、未决边界，或直接结束
- 半角引号 `""` → 改成「」，排版更稳
- 通篇「据……统计」句式雷同 → 换几种说法，但来源不能丢
- 同一数据在文中重复出现两次 → 删掉一处（重复也是机器痕迹）

## 改完的自检

- [ ] 数字集合与初稿一致（跑对账脚本）
- [ ] 标题层级、表格、图片引用数量一致
- [ ] 通篇没有「值得注意的是」「不难看出」「综上所述」
- [ ] 连续三句长度结构不同
- [ ] 结尾不是口号
- [ ] 字数符合体裁（A 类 2500–5000；B 类无下限，别硬补）
- [ ] **B 类：逐段查过虚构细节，原话里没有的数量/动作/环境已删净**
